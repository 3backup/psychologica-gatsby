## Rozmiar HTML strony głównej — 20.10.2026

Odchudzony arkusz CSS pozostaje inline, aby pierwsze wyświetlenie na telefonie nie czekało na dodatkowe blokujące żądanie sieciowe. Fonty zachowują dotychczasowe pliki i reguły, ale wszystkie formaty są emitowane do osobnych plików; nieużywane warianty nie powiększają już CSS. Arkusz z hashem nadal jest generowany przez Gatsby. Nie zmieniamy rodzin, grubości, treści ani układu.

Duże, niezmienne SVG nagłówka, stopki i dekoracji hero oraz ikony oferty, spotkań zdalnych i etapów współpracy są importowane z `src/assets` jako pliki z hashem. Ikony poniżej pierwszego ekranu mają natywne opóźnione ładowanie. Małe ikony nadal mogą być renderowane inline. Obrazki zachowują rozmiary, a link do strony głównej zachowuje nazwę dostępną; dekoracyjne logo ma pusty alt i `aria-hidden`. Nagłówki Vercel ustawiają roczny cache `immutable` wyłącznie dla plików z hashem: `styles.*.css` i zasobów Gatsby w `/static/`.

Statyczny HTML używa udokumentowanego API Gatsby `replaceRenderer` i `renderToString`. Bufor strumieniowego renderera React 18 wstawiał bajty NUL przed polskimi znakami po zmianie granic fragmentów przy krótszym kodzie SVG; problem odtworzono na Node 22 i 24. Zapis całego tekstu eliminuje padding bez poprawiania danych CMS i bez aktualizacji React/Gatsby. Kontrola kompilacji odrzuca NUL we wszystkich wygenerowanych plikach HTML. W tym projekcie strony są statyczne i nie korzystają z asynchronicznego Suspense ani Gatsby Slices.

`scripts/verify-home-html.cjs` jest obowiązkową częścią `onPostBuild` i kontroli rzeczywistej produkcji. Blokuje przekroczenie 160 000 B HTML strony głównej, 80 000 B osadzonego CSS, brak arkusza/dużych SVG, ponowne osadzenie fontów w CSS i brak rocznego cache zasobów. Wymaga odchudzonego CSS inline i odrzuca blokujące ładowanie globalnego arkusza. Kontrola lokalna sprawdza pliki i konfigurację; po publikacji wymaga rzeczywistego HTTP 200 oraz nagłówków cache. Weryfikator treści lokalizacji rozpoznaje dekoracyjne logo także jako zewnętrzny obraz.
